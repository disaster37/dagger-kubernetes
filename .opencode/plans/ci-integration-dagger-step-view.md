# Plan: CI integration — rebuild Dagger's internal step view (nested steps, state, logs) in CI (Jenkins Blue Ocean)

## 0. Summary

Today a CI (Jenkins) invokes **one** Dagger function through the
`dagger-kubernetes-ci` wrapper / `daggerKubernetes.groovy` shared library and
sees a **single monolithic step** with one log stream. The user wants the CI to
surface Dagger's **internal execution tree** — every nested call/operation the
engine runs — as **individual nested steps**, each with its own **state**
(pending/running/succeeded/failed) and its own **live logs**, rendered in
**Jenkins Blue Ocean**.

The good news: the supervisor **already rebuilds this exact tree server-side**.
`repository.SpanTreeReconstructor` reconstructs the nested span tree from the
OTLP traces the engine exports (`/v1/traces` → Tempo), merges duplicate
start/finish span records, and links children to parents; per-span logs are
already correlated by `span_id` in Loki; the UI already renders the nested tree
with per-step logs. The gap is **client-side**: the CI wrapper never consumes
that tree.

This plan closes the gap by adding a **normalized CI step-event stream** built
in the `dagger-kubernetes-ci` wrapper from the supervisor's existing REST
surface, and a **Jenkins shared-library consumer** that renders nested stages.
The core diffing/event logic lives in a testable `internal/service` package;
the Jenkins rendering is a swappable sink, and a dedicated Jenkins plugin is
documented as the higher-fidelity escape hatch.

**Primary data source:** the supervisor's reconstructed span tree + per-span
logs + live SSE (single source of truth, identical to the pipeline UI). No new
supervisor endpoint is required. **Fallback data source:** Dagger engine
GraphQL/`--progress` telemetry read directly by the wrapper (documented in
§13, marked "needs verification").

## 1. Goal and non-goals

### Goal

- Rebuild Dagger's internal call/operation tree in the CI integration and
  expose it as **nested steps** with **per-step state** and **per-step live
  logs** in Jenkins Blue Ocean.
- Reuse the supervisor's already-reconstructed span tree + logs as the single
  source of truth (the CI view matches the platform pipeline UI).
- Keep the wrapper a drop-in: with the feature disabled, behaviour is
  byte-for-byte today's behaviour.

### Non-goals (explicitly out of scope)

- Changing how the **supervisor** reconstructs traces (the `SpanTreeReconstructor`
  and Loki log correlation already work).
- A full Jenkins **plugin** (`.hpi`) with per-step `FlowNode` instrumentation —
  documented in §2.4 as a follow-up escape hatch, not implemented here.
- Live per-step state for **GitHub Actions / Drone** (they keep their existing
  annotation/summary behaviour; the event stream is CI-agnostic and reusable
  later).
- Resuming/partitioning a single `dagger call` into multiple `dagger call`
  invocations (Dagger does not support resuming into the middle of a function's
  call tree; the tree is observed, not re-driven).

### How this maps to Jenkins Blue Ocean

Blue Ocean's pipeline graph is generated by the Jenkins **Pipeline plugin** as
**flow nodes** are created at runtime by `stage()` / step invocations. The
mapping we implement:

| Dagger / supervisor concept | Jenkins concept |
|---|---|
| Trace (one `dagger call`) | One Jenkins **run** (already the case) |
| `SpanNode` (operation) | A nested **`stage()`** (scripted pipeline) |
| `SpanNode.ParentSpanID` | Nested stage under its parent stage |
| `SpanNode.Status` running/success/failed | Stage **state**: running / success / failure (`catchError` / `stageResult`) |
| `LogEntry.SpanID` + `Line` | `echo` lines inside the owning stage (per-step console log) |
| Root span status success/failed | Overall **build result** (wired to the `dagger` exit code) |

Each `StepNode` gets a **stable id** (the span id), a **parent id**, a **name**
(span name, sanitized), a **depth**, and **state transitions**
(`pending → running → succeeded|failed`). The wrapper emits these as an ordered
normalized event stream; the shared library consumes it and renders nested
`stage()` blocks.

## 2. Chosen approach + rationale + rejected alternatives

### 2.1 Chosen approach

1. **Data source (primary):** the CI wrapper polls the supervisor's existing,
   auth-gated REST surface — `GET /api/v1/traces/:traceID` (reconstructed span
   tree) and `GET /api/v1/traces/:traceID/logs` (per-span logs) — and is
   woken by the existing `GET /api/v1/traces/:traceID/live` SSE "re-fetch"
   pings. The wrapper sets `OTEL_EXPORTER_OTLP_TRACES_LIVE=1` so the engine
   exports in-flight spans live (otherwise spans only appear at completion).
2. **Event model:** a new `internal/service.StepEventBuilder` diffs successive
   tree+log snapshots and emits an **ordered, idempotent** `[]domain.CIEvent`
   stream (`node_started`, `node_finished`, `log_chunk`, `pipeline_done`). All
   the hard edge cases (dedupe, out-of-order, orphans, depth clamp, log
   watermarking) live here, unit-tested to 100%.
3. **Wire format:** an `NDJSONEventSink` writes one JSON object per line — a
   stable, CI-agnostic protocol consumed by the Jenkins shared library (and,
   later, Drone/GHA/plugin).
4. **Rendering:** the Jenkins shared library gains a `dynamicStages` mode that
   consumes the NDJSON stream and renders **nested scripted-pipeline `stage()`**
   blocks with `echo` per-step logs and `catchError`-derived per-stage status.
   Live rendering is achieved by launching the wrapper in the background of the
   enclosing `node` and rendering stages from the event stream as it grows.

### 2.2 Rationale

- **Reuses the platform's own reconstruction.** The supervisor already has the
  authoritative tree + log correlation + dedupe + status mapping. Rebuilding it
  again in the wrapper would duplicate `SpanTreeReconstructor` and drift from
  the UI. The CI view **must** match the pipeline UI.
- **No supervisor change required** for v1: the diff logic is a pure service
  (client-side), so the feature is testable end-to-end without touching the
  control plane.
- **CI-agnostic seam.** The hard part (snapshot diffing) is separated from the
  Jenkins-specific part (Groovy rendering), so the same stream can drive other
  CIs or a future plugin without rework.
- **Non-breaking.** Feature-gated behind `ci.jenkins.dynamic_stages` (which is
  already documented as "split Dagger steps into Jenkins stages" but is
  currently a no-op).

### 2.3 Rejected alternatives

- **Static Jenkinsfile with pre-declared nested stages.** Rejected: the Dagger
  tree is not known until runtime, and a monolithic function's internal calls
  vary per run (cache hits, module resolution). Cannot express dynamic nesting
  statically.
- **Scraping the Blue Ocean / Pipeline Steps REST API to inject nodes.**
  Rejected: Blue Ocean's API is read-only for the graph; there is no supported
  write path to create arbitrary nested flow nodes from outside the flow.
- **Client-side Dagger GraphQL (`currentFunctionCall` / `_experimental`) as the
  primary source.** Rejected as primary because (a) it duplicates the
  supervisor's reconstruction, (b) the experimental surface is unstable and
  version-dependent, and (c) it would diverge from the UI. Kept as a documented
  fallback (§13) for zero-supervisor or low-latency cases.
- **Re-driving each Dagger sub-step as a separate `dagger call` stage.**
  Rejected: Dagger cannot resume into the middle of a function's call tree;
  each `dagger call` is an independent invocation (fast via cache, but not the
  same tree).
- **Post-run replay only (emit nested `stage()` after `dagger` exits).**
  Rejected as insufficient: the user wants live state + logs, and Jenkins
  cannot append stages to an already-completed flow.

### 2.4 Fidelity ceiling + documented escape hatch

Scripted-pipeline nested `stage()` gives **nested stages with per-stage console
logs and statuses** — this satisfies the user's ask. True **per-step** Blue
Ocean flow nodes (each Dagger span as its own clickable *step* with its own log
pane, live) requires a Jenkins **plugin** implementing a `Step` that spawns
child `FlowNode`s via the `FlowNode`/`StepContext` API. That is a separate
deliverable (new repo/artifact, Jenkins plugin SDK). The NDJSON wire protocol
in this plan is deliberately designed to feed that plugin unchanged.

## 4. Data structures (domain + service + repository)

### 4.1 `internal/domain/ci_steps.go` (new, stdlib only)

```go
package domain

import "time"

// StepState is the CI-visible lifecycle state of one Dagger operation (span).
type StepState string

const (
	StepStatePending   StepState = "pending"   // discovered via parent, not started
	StepStateRunning   StepState = "running"   // start record seen, no finish record
	StepStateSucceeded StepState = "succeeded" // finished with OK
	StepStateFailed    StepState = "failed"    // finished with error
)

// StepNode is the CI-facing view of one Dagger operation (span), rebuilt from
// the supervisor's reconstructed span tree.
type StepNode struct {
	ID         string    `json:"id"`          // stable; the span id (base64, as Tempo returns it)
	ParentID   string    `json:"parent_id"`   // "" for the root step
	Name       string    `json:"name"`        // sanitized span name
	State      StepState `json:"state"`
	Depth      int       `json:"depth"`       // 0 = root
	StartedAt  time.Time `json:"started_at"`
	FinishedAt time.Time `json:"finished_at,omitempty"`
}

// LogChunk is a bounded batch of log lines attributed to a node.
type LogChunk struct {
	NodeID    string    `json:"node_id"`
	Timestamp time.Time `json:"timestamp"`
	Lines     []string  `json:"lines"`
}

// CIEventType enumerates the normalized CI event stream.
type CIEventType string

const (
	CIEventNodeStarted  CIEventType = "node_started"
	CIEventNodeFinished CIEventType = "node_finished"
	CIEventLogChunk     CIEventType = "log_chunk"
	CIEventPipelineDone CIEventType = "pipeline_done" // carries Status: success|failed|canceled
)

// CIEvent is the normalized, ordered event emitted by the step-event builder.
type CIEvent struct {
	Seq       int64       `json:"seq"`       // monotonic within a pipeline
	Type      CIEventType `json:"type"`
	TraceID   string      `json:"trace_id"`
	Timestamp time.Time   `json:"timestamp"`
	Node      *StepNode   `json:"node,omitempty"`   // node_started / node_finished
	Log       *LogChunk   `json:"log,omitempty"`    // log_chunk
	Status    string      `json:"status,omitempty"` // pipeline_done ("success"|"failed"|"canceled")
	Error     string      `json:"error,omitempty"`  // failure reason (node_finished / pipeline_done)
}

// CIEventSink consumes normalized CI events. Implementations render to a CI
// system (NDJSON for Jenkins/Drone, a future plugin protocol, a debug file).
type CIEventSink interface {
	Emit(e CIEvent) error
	Flush() error
}

// TraceSnapshotSource is the data source the CI wrapper uses to rebuild the
// step tree: the supervisor's span-tree reconstruction + per-span logs. The
// wrapper's HTTP client implements it (repository.SupervisorTraceClient).
type TraceSnapshotSource interface {
	GetTrace(traceID string) (*TraceInfo, error)
	QueryTraceLogs(traceID string, start, end time.Time, limit int) ([]LogEntry, error)
}
```

Notes:
- `TraceSnapshotSource` is a **composite** of the already-defined
  `TraceRepository.GetTrace` and `LogRepository.QueryTraceLogs` signatures; the
  supervisor client satisfies both without new method bodies.
- `StepNode.ID` uses the span id exactly as Tempo/`SpanTreeReconstructor`
  returns it (base64 8-byte) and as `normalizeSpanID` yields for logs, so
  log→node attribution is a plain string compare.

### 4.2 `internal/service/ci_steps.go` (new)

```go
package service

import (
	"sync"
	"time"

	"github.com/disaster/dagger-kubernetes/internal/domain"
)

// StepEventBuilder diffs successive tree+log snapshots into an ordered,
// idempotent normalized CI event stream. It is safe for concurrent use.
type StepEventBuilder struct {
	mu      sync.Mutex
	maxDepth int
	seen    map[string]*domain.StepNode // last emitted state per node id
	logMark time.Time                   // log watermark (exclusive)
	seq     int64
}

// NewStepEventBuilder returns a builder that clamps the tree at maxDepth
// (nodes deeper than maxDepth are folded into their deepest emitted ancestor;
// their logs are attributed to that ancestor). maxDepth <= 0 means unlimited.
func NewStepEventBuilder(maxDepth int) *StepEventBuilder

// Advance diffs the current snapshot (trace tree + logs) against the previous
// one and returns the ordered events to emit, updating internal state.
// It is idempotent: an unchanged snapshot returns an empty slice.
// A nil trace returns a wrapped error; a tree with no resolvable root emits
// nothing yet (the run is still ingesting).
func (b *StepEventBuilder) Advance(trace *domain.TraceInfo, logs []domain.LogEntry) ([]domain.CIEvent, error)
```

`Advance` behaviour (the unit-test contract):

1. Flatten the `SpanNode` tree DFS into `(node, depth)` respecting `maxDepth`;
   defensively dedupe by span id (first wins) even though the server already
   dedupes.
2. Map `SpanNode.Status` → `StepState`:
   `""|"running"` → `running`; `"success"` → `succeeded`; `"failed"` → `failed`.
3. For each node:
   - unseen → emit `node_started` (`pending→running`), then (if already
     terminal) `node_finished` back-to-back.
   - seen and state changed `running → succeeded|failed` → emit `node_finished`
     with `Error` (from `trace` root/failing span attributes if present).
4. Orphan resolution: a node whose `ParentID` is absent from the snapshot is
   re-parented to the root; if no root exists yet, defer (emit nothing for it).
5. Logs: sort by `Timestamp`, drop entries `<= logMark`, batch remaining lines
   into `LogChunk`s (max `ciLogChunkLines` lines and `ciLogChunkBytes` bytes),
   attribute by `SpanID` (unknown span → root; if no root, defer). Advance
   `logMark` to the last emitted timestamp.
6. Pipeline completion: once the root span carries a terminal status (or
   `trace.Status` is terminal), emit a single `pipeline_done` with the mapped
   status (`success`/`failed`/`canceled`). Emitted at most once.

### 4.4 `internal/repository/supervisor_client.go` (new)

```go
package repository

import (
	"context"
	"net/http"
	"time"

	"github.com/disaster/dagger-kubernetes/internal/domain"
)

// SupervisorTraceClient reads the reconstructed span tree + logs from the
// supervisor's REST API. Implements domain.TraceSnapshotSource.
type SupervisorTraceClient struct {
	baseURL    string // e.g. https://supv.example.com
	token      string // Bearer token
	httpClient *http.Client
}

var _ domain.TraceSnapshotSource = (*SupervisorTraceClient)(nil)

// NewSupervisorTraceClient builds a client with an explicit timeout so a
// stalled supervisor cannot hang a CI job (mirrors cmd/ci's cliHTTPClient).
func NewSupervisorTraceClient(baseURL, token string, timeout time.Duration) *SupervisorTraceClient

// GetTrace fetches GET /api/v1/traces/{id} (Bearer auth) and decodes the
// domain.TraceInfo. Non-200 → wrapped error.
func (c *SupervisorTraceClient) GetTrace(traceID string) (*domain.TraceInfo, error)

// QueryTraceLogs fetches GET /api/v1/traces/{id}/logs (Bearer auth) and
// decodes []domain.LogEntry. start/end/limit are passed through as query
// params.
func (c *SupervisorTraceClient) QueryTraceLogs(traceID string, start, end time.Time, limit int) ([]domain.LogEntry, error)
```

All requests use `http.NewRequestWithContext` + `Authorization: Bearer <token>`
and `%w`-wrapped errors (e.g. `fmt.Errorf("get trace %s: %w", traceID, err)`).

Changes to `run()`:

1. After env setup, add `_ = os.Setenv("OTEL_EXPORTER_OTLP_TRACES_LIVE", "1")`
   (always; harmless when unused, required for live span export).
2. Replace the single `cmd.Stderr = io.MultiWriter(os.Stderr, &logBuf)` with a
   `liveCaptureWriter` that feeds a `traceID chan string` (buffered 1) while
   still writing to `os.Stderr` and `&logBuf`.
3. If `--steps` and a trace id is captured, start `streamSteps` in a goroutine
   wired to `SupervisorTraceClient` + `StepEventBuilder` + `NDJSONEventSink(os.Stdout)`.
   The NDJSON goes to **stdout** (reserved for the event protocol in `--steps`
   mode); the human pipeline-view link + `dagger` stderr stay on stderr.
4. After `cmd.Run()`, do one final `Advance` (to flush terminal state), then
   `sink.Flush()`.
5. Return `err` from `cmd.Run()` unchanged (dagger exit code is authoritative).

### 5.2 `ci-integrations/jenkins/daggerKubernetes.groovy` (changed)

```groovy
// Params additions: dynamicStages (bool, default env/params), stepsPollInterval,
// stepsMaxDepth, timeoutMinutes.
def call(Map params = [:], Closure body)

// renderStepTree(reader, node) — recursive scripted-pipeline renderer.
// Consumes the wrapper's NDJSON stream and opens nested stage(name){...}
// blocks, echoing each node's log lines inside its stage.
// Node state → stage result via catchError / stageResult so Blue Ocean shows
// per-stage success/failure.
void renderStepTree(def events, def root)

// normalizeStageName(name, id) -> String — sanitize a span name for use as a
// Jenkins stage name (Jenkins tolerates most chars, but strip control chars,
// collapse whitespace, disambiguate with a short id suffix on collision).
String normalizeStageName(String name, String id)
```

The `call` body, in `dynamicStages` mode:

1. Wrap the run in `timeout(time: params.timeoutMinutes ?: 30, unit: 'MINUTES')`.
2. Launch the wrapper in the background of the enclosing `node`, writing NDJSON
   to a per-build temp file (`${WORKSPACE}/.dagger-kubernetes/steps-${env.BUILD_NUMBER}.ndjson`)
   and the `dagger` stderr to a log file. Capture the wrapper PID.
3. Loop: read new NDJSON lines (incremental `sh 'cat file | tail -n +<offset>'`),
   and drive the recursive `renderStepTree` so nested `stage()` blocks are
   opened/closed as events arrive; `echo` each `log_chunk`'s lines inside the
   owning stage.
4. On `pipeline_done`, stop the loop; wait for the wrapper PID; propagate the
   `dagger` exit status as the build result.

## 7. Edge cases

| Edge case | Handling |
|---|---|
| Duplicate span ids | Server (`mergeSpanNode`) already dedupes; `StepEventBuilder` defensively dedupes (first-wins) in its flatten step. |
| Out-of-order events / Tempo indexing lag | The builder is **snapshot-diff** based, not stream-order based, so out-of-order indexing self-heals on the next poll. Missing parent → re-parent to root; no root → defer. |
| Log chunks before node creation | Builder buffers per-node lines; emits the `log_chunk` only after its node's `node_started` (or attributes to root if the node never appears). |
| Orphan nodes (parent absent) | Re-parent to root. If no root yet, defer until a later snapshot. |
| Large log volume / backpressure | Logs batched into bounded `LogChunk`s (max lines/bytes); `NDJSONEventSink` flushes per line and the wrapper's channel is bounded + coalescing (drop-oldest) so a slow consumer cannot stall `dagger`. |
| Network interruption mid-stream | `streamSteps` retries with backoff and logs via logrus; on persistent failure it degrades to today's single-stage + link behaviour and **never fails the build**. |
| Function failure propagation | `dagger` exit code is authoritative for the build result; failing span → `node_finished(state=failed)`; root terminal status → `pipeline_done(status=failed)`. |
| Nested depth limit | `steps_max_depth` clamps the tree; deeper nodes are folded into their deepest emitted ancestor (logs attributed there) so the UI never overflows. |
| Concurrent pipelines / shared files | NDJSON file is per-build (`steps-${BUILD_NUMBER}.ndjson`) and per-`WORKSPACE`; span ids are unique per trace so node ids never collide across builds. |
| No trace id (engine failed before printing / no-dagger fallback) | `streamSteps` never starts; wrapper falls back to today's single-stage + link behaviour. |
| Long quiet steps / Jenkins timeout | Shared library wraps the whole run in a configurable `timeout(...)`; default 30 min; the poller emits keep-alive no-ops by remaining quiet without holding resources. |
| Empty / no steps yet | Builder emits nothing until a root is resolvable; Jenkins shows the single enclosing stage (running) until the first `node_started`. |
| Malformed trace id from live capture | Only ids matching `traceIDRe` are accepted; anything else is ignored (same rule as today). |

## 8. Error handling + validation

### Error handling

- **`%w` wrapping everywhere** (repo rule): e.g.
  `return nil, fmt.Errorf("get trace %s: %w", traceID, err)`.
- **Stream errors are non-fatal**: logged at `Warn`/`Debug` (logrus fields
  `trace_id`, `attempt`), retried, and the build result is unaffected.
- **`dagger` errors are fatal** and surface verbatim to the user (the CI result).
- **Sink `Emit`/`Flush` errors** are logged; `Flush` failure is logged but does
  not change the returned `dagger` error.
- **Never log the token**; the supervisor client sets `Authorization` and never
  logs headers.

### Validation rules

| Rule | Where |
|---|---|
| `traceID` must match `^[a-f0-9]{32,}$` (wrapper) and `ValidTraceID` hex on the supervisor side (already enforced) | `cmd/ci` live capture; `SupervisorTraceClient` |
| `steps_max_depth` must be `>= 0` (0 = unlimited); invalid → config validation error | `config.Load` `validateCIConfig` |
| `steps_poll_interval` must be `> 0` (0 would hot-loop the API) | `config.Load` `validateCIConfig` |
| Node id / parent id non-empty; empty → node skipped | `StepEventBuilder` |
| Stage names sanitized: strip control chars, collapse whitespace, cap length, disambiguate with short id suffix | `normalizeStageName` (Groovy) |
| Log chunk bounded (`ciLogChunkLines`, `ciLogChunkBytes`) | `StepEventBuilder` |

## 13. Assumptions & open questions

**Assumptions (flagged for confirmation):**

1. **Primary data source = supervisor's reconstructed tree** (not direct Dagger
   GraphQL from the wrapper). This makes the CI view identical to the pipeline
   UI and requires no supervisor change. *Alternative:* read Dagger engine
   telemetry directly (`--progress`, or `_experimental` nested-call GraphQL,
   or the `currentFunctionCall` API) for lower latency / no-supervisor cases —
   the exact `_experimental`/`currentFunctionCall` surface is version-dependent
   and **needs verification** if pursued; it is not required for v1.
2. **Live span export requires `OTEL_EXPORTER_OTLP_TRACES_LIVE=1`.** Confirmed
   from Dagger's telemetry docs; without it spans (and thus per-step state) only
   appear at completion.
3. **Jenkins rendering = scripted-pipeline nested `stage()`** via the shared
   library (in-repo deliverable). This gives nested stages + per-stage console
   logs + per-stage status in Blue Ocean. True per-step *flow nodes* require a
   Jenkins **plugin** — a separate deliverable, out of scope here.
4. **`ci.jenkins.dynamic_stages`** (currently documented but a no-op) becomes
   the feature gate; new keys `steps_poll_interval`/`steps_max_depth` are added.
5. **NDJSON on stdout** in `--steps` mode is the wrapper's protocol channel
   (stderr remains for `dagger` output + the human link). Confirm no existing
   consumer parses wrapper stdout.

**Open questions for the implementer to verify during implementation:**

- Exact `dagger` CLI stderr wording for the trace id (the `[a-f0-9]{32,}` regex
  is already in use, but confirm the id is emitted before completion so live
  capture works).
- Whether Tempo's `/api/traces/{id}` returns partial trees quickly enough for a
  ~2s poll (the existing `SpanTreeReconstructor` already handles partial trees;
  tune `steps_poll_interval` if not).
- Jenkins CPS tolerance of deeply nested dynamic `stage()` in a shared library
  (the known fragile spot — hence the `steps_max_depth` clamp and the plugin
  escape hatch).

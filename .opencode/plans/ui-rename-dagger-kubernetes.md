# Plan: Rename UI branding "Dagger Cache" → "Dagger Kubernetes"

## Goal
Change all **user-facing UI branding** from "Dagger Cache" to "Dagger Kubernetes" in the
Vue SPA and its embedded build artifacts. Internal identifiers, file paths, config
keys, module paths, binary names, and protocol strings remain unchanged.

## Scope rule
A string is in scope iff it is rendered to a user in the **web UI** (HTML title,
navbar/logo, rendered template text) or in **HTTP responses / SSE payloads / HTML
templates** produced by the server. CLI help text, CI log echoes, GitHub Action
descriptions, and standalone docs are flagged separately below (borderline).

## 2. Rebuild UI artifacts (generated, do NOT hand-edit)

The brand string "Dagger Cache" also appears in built/minified artifacts as a string
literal baked in from `App.vue`. These are regenerated by the Vite build:

- `ui/dist/index.html` (line 6 — title)
- `ui/dist/assets/index-n4bAtmap.js` (line 39 — minified bundle containing the
  App.vue logo literal; the filename hash will change on rebuild)
- `internal/handler/ui-dist/index.html` (tracked pre-built copy embedded via
  `//go:embed all:ui-dist` in `internal/handler/ui.go`)
- `internal/handler/ui-dist/assets/index-*.js` (tracked pre-built copy)

### Rebuild procedure
```sh
cd ui
npm ci
npm run typecheck
npm run build          # regenerates ui/dist/
cd ..
rm -rf internal/handler/ui-dist
cp -r ui/dist internal/handler/ui-dist   # keep //go:embed valid for local go build
```
The `Dockerfile` rebuilds `ui/` → `internal/handler/ui-dist/` itself (line 10, 20),
so Docker/CI builds pick up the source change automatically. The tracked
`internal/handler/ui-dist/` copy must still be regenerated in-tree so that local
`go build ./...` (without Docker) embeds the new branding.

Note: the hashed asset filename (`index-n4bAtmap.js`) will change after rebuild.
Do not attempt to preserve the old hash. Replace the whole
`internal/handler/ui-dist/assets/` directory.

## 3. Data structures / constants / signatures
None. The brand strings are plain text literals in Vue templates and an HTML
`<title>`. No Go constant, struct field, map key, route path, CSS selector, or
label is derived from the brand string. No function signature changes.

## 4. Edge cases & case variations

- **Case forms present in UI:** only "Dagger Cache" (title case, single space).
  No "DAGGER CACHE", "dagger cache", or "DaggerCache" forms exist in UI files.
- **Hyphenated form `dagger-cache`:** appears in UI as the **file path**
  `~/.dagger-cache.env` in `ui/src/views/Connect.vue` (lines 142 and 195). This is
  a **file path convention**, not the brand name. Renaming it would break existing
  users' shell setups and the `.bashrc` snippet the UI generates. See §6 DO NOT
  CHANGE. (Flagged as explicit decision in §8.)
- **Embedded in larger strings:** the title `"Dagger Cache - Pipeline View"` —
  replace only the "Dagger Cache" token, keep " - Pipeline View" suffix.
- **HTML entities:** none; the strings are plain ASCII text in UTF-8 HTML.
- **Minified JS:** the brand literal is embedded in the bundled `index-*.js`.
  Must be regenerated via build, never hand-edited.
- **`ui/package.json` `"name": "dagger-cache-ui"`** and `ui/package-lock.json`
  `"name": "dagger-cache-ui"`: npm package name, an internal identifier not
  displayed in the UI. DO NOT CHANGE (see §6).

---

## 5. Error handling / validation considerations

- The brand string is **not** used as a map key, route path, CSS selector, k8s
  label, Helm value, or config key anywhere in the UI. Renaming it cannot break
  routing, embedding, or builds.
- `//go:embed all:ui-dist` requires the directory to exist and be non-empty. The
  rebuild procedure in §2 preserves this. If `internal/handler/ui-dist/` is left
  stale, `go build` still succeeds but embeds the OLD branding — the validation
  step below catches this.
- The hashed JS filename changes on rebuild; `index.html` references it by hash,
  so both must come from the same build (the `cp -r` in §2 guarantees this).
